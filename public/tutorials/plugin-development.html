Introdução

O sistema de plugins do Lunar Base permite estender as funcionalidades do sistema de forma totalmente modular e desacoplada. Cada plugin funciona como um mini-ecossistema independente, contendo suas próprias rotas, controladores, visões, modelos, migrações de banco, documentação e pontos de configuração.

Comando de Geração Rápida

O Lunar Base oferece um comando Artisan que gera a estrutura completa de um plugin automaticamente:

BASHphp artisan plugin:create "NomeDoPlugin" "Descrição opcional do plugin"

Opções Interativas:

Durante a execução, o comando perguntará se o módulo requer:

  • Banco de dados? - Cria as pastas Models/ e database/migrations/ com arquivos de exemplo.
  • Controller e Rotas? - Cria Http/Controllers/ e o arquivo routes.php.
  • Views? - Cria resources/views/ e a pasta obrigatória resources/help-views/ com o arquivo help.blade.php.
Assets Públicos: O comando cria automaticamente o link simbólico (ou junction no Windows) em public/plugins/nome-do-plugin apontando para plugins/NomeDoPlugin/resources/assets.

Manifesto (plugin.json) e Configurações

O arquivo plugin.json armazena os metadados do plugin, os requisitos técnicos do sistema e as variáveis customizáveis que o usuário pode sobrescrever em config/pluginSettings.php:

JSON{
    "name": "Tracker",
    "description": "Estatísticas de acesso, visualizações de páginas e eventos.",
    "version": "1.1.0",
    "provider": "Plugins\\Tracker\\TrackerServiceProvider",
    "requirements": {
        "composer": {
            "stevebauman/location": "^7.0"
        },
        "php": ">=8.1"
    },
    "configurable": {
        "dashboardDays": {
            "type": "integer",
            "default": 30,
            "description": "Quantidade de dias retroativos no Dashboard."
        },
        "topPagesLimit": {
            "type": "integer",
            "default": 10,
            "description": "Limite de páginas exibidas no card."
        }
    }
}

Como ler os valores no código PHP:

No seu Controller ou ServiceProvider, utilize o helper setting() com fallback para as configurações:

PHP$days = (int) setting('pluginSettings.Tracker.dashboardDays', 30);
$limit = (int) setting('pluginSettings.Tracker.topPagesLimit', 10);

Arquivo de Mudanças (CHANGELOG.md)

Todo plugin deve manter um arquivo CHANGELOG.md na raiz da sua pasta. Quando uma atualização fica disponível no Marketplace de Plugins, o sistema lê esse arquivo e renderiza um modal visual destacando as novidades, melhorias e correções da versão.

Estrutura recomendada para o CHANGELOG.md:

MARKDOWN# Changelog

## [1.1.0] - 2026-08-30
### Added
- Novo relatório de picos de acesso por horário (00h às 23h).
- Suporte a geolocalização via pacote stevebauman/location.

### Changed
- Refatoração dos gráficos para usar o componente x-chart.

### Fixed
- Correção de cálculo de visitantes únicos por IP diário.

Ajuda do Plugin e Componentes Auxiliares

O arquivo resources/help-views/help.blade.php é obrigatório. Ele é exibido quando o administrador clica no ícone de interrogação () na lista de plugins em Admin → Plugins.

Para orientar o usuário sobre requisitos e customizações sem escrever código manual, utilize os dois componentes globais do Core no final do arquivo:

BLADE<div class="plugin-help-content">
    <header>
        <h3><x-lucide-activity class="lucid-icon" /> Tracker</h3>
        <p>Monitoramento de tráfego, visualizações e conversões do site.</p>
    </header>

    <h4>Como funciona</h4>
    <p>O plugin captura pageviews no front-end de forma anônima e sem cookies.</p>

    <!-- 💡 Gera o bloco PHP de config/pluginSettings.php baseado no plugin.json -->
    <x-configurable-plugin-values plugin="Tracker" />

    <!-- 💡 Checa se as dependências do Composer e PHP estão instaladas no vendor -->
    <x-plugin-dependencies plugin="Tracker" />
</div>

Ajuda Contextual para Telas da Admin

Se o seu plugin cria telas na área administrativa (ex: admin.tracker.index, admin.tracker.hourly), você pode adicionar ajuda contextual no botão de interrogação do cabeçalho da página.

Como fazer:

Basta criar uma view dentro da pasta resources/views/help/ do plugin, com o nome da rota substituindo pontos por hífens:

  • Rota: admin.tracker.index $\rightarrow$ Arquivo: resources/views/help/admin-tracker-index.blade.php
  • Rota: admin.tracker.hourly $\rightarrow$ Arquivo: resources/views/help/admin-tracker-hourly.blade.php

Registro de Tipos de Publicação (PublicationTypes)

Se o seu plugin introduzir uma nova entidade de conteúdo gerenciável (como Cursos, Imóveis, Eventos), registre-a no PublicationTypes para integrá-la automaticamente às Taxonomias e ao módulo de Transferência de Conteúdo (Export/Import JSON).

Como Registrar no boot() do ServiceProvider:

PHPuse App\Support\PublicationTypes;
use Plugins\Caminho\Models\Course;

public function boot(): void
{
    // Registra o tipo 'course' no sistema
    PublicationTypes::register(
        'course',
        'Cursos',
        Course::class,
        ['classes', 'terms'] // Relacionamentos incluídos na exportação JSON
    );
}

Benefícios Automáticos:

  • Taxonomias Dedicadas: Em Admin → Taxonomias, o tipo "Cursos" aparecerá como opção de checkbox para vincular categorias ou tags exclusivas para cursos.
  • Exportação/Importação JSON: Em Admin → Ferramentas → Transferência de Conteúdo, o tipo aparecerá para ser exportado e importado entre servidores.

Ciclo de Vida (ServiceProvider)

O ServiceProvider conecta todos os componentes do plugin ao ciclo de vida do Laravel:

PHPnamespace Plugins\Tracker;

use Illuminate\Support\ServiceProvider;
use App\Support\AdminMenu;
use Plugins\Tracker\Http\Middleware\TrackPageViews;

class TrackerServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        // 1. Registra as rotas durante o register()
        $routesFile = __DIR__ . '/routes.php';
        if (file_exists($routesFile)) {
            $this->loadRoutesFrom($routesFile);
        }
    }

    public function boot(): void
    {
        // 2. Carrega Migrations e Views com Namespace exclusivo
        $this->loadMigrationsFrom(__DIR__ . '/database/migrations');
        $this->loadViewsFrom(__DIR__ . '/resources/views', 'tracker');

        // 3. Registra o Item na Sidebar da Administração
        AdminMenu::add([
            'label'      => 'Tráfego',
            'icon'       => 'activity',
            'route'      => 'admin.tracker.index',
            'active'     => 'admin.tracker.*',
            'permission' => 'view-dashboard',
        ], 'Temas', 1);

        // 4. Injeta Middleware no Grupo 'web'
        $this->app['router']->pushMiddlewareToGroup('web', TrackPageViews::class);
    }
}

Banco de Dados (Migrations & Models)

As migrações do plugin são carregadas automaticamente via $this->loadMigrationsFrom(...) sem necessidade de movê-las para a pasta raiz do Laravel.

Exemplo de Model com Trait HasMeta:

Se a sua entidade precisar de armazenamento de campos dinâmicos em formato JSON, use a trait nativa HasMeta:

PHPnamespace Plugins\Tracker\Models;

use Illuminate\Database\Eloquent\Model;
use App\Traits\HasMeta;

class TrackerSettings extends Model
{
    use HasMeta;

    protected $table = 'tracker_settings';
    protected $fillable = ['name', 'meta'];
}

Boas Práticas de Organização

  • Nomenclatura Única: Use PascalCase para pastas e namespaces (ex: Plugins\Tracker).
  • Namespaces de Views: Sempre defina um namespace exclusivo e em minúsculas (ex: 'tracker') no loadViewsFrom() para evitar conflitos de templates.
  • Isolamento de Assets: Injete estilos e scripts usando add_script() e add_inline_script() no `@footerAssets`, mantendo o código JS em arquivos estáticos separados.
  • Checagem de Dependências: Use class_exists() para verificar pacotes opcionais antes de executar métodos que possam falhar caso o pacote não esteja no vendor/.
