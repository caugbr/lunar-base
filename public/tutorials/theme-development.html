Introdução

O sistema de temas do Lunar Base permite transformar completamente a identidade visual do site público. Os temas herdam a lógica e views do core por padrão, mas dão total liberdade para que qualquer template ou folha de estilo seja substituído de forma transparente.

Comando de Geração Rápida

O Lunar Base oferece um comando Artisan que gera a estrutura base de um novo tema automaticamente, incluindo diretórios, manifesto, templates e link simbólico para assets públicos:

BASHphp artisan theme:create "Nome do Tema" "Descrição opcional do tema"

O que é gerado automaticamente:

themes/
└── NomeDoTema/
    ├── resources/
    │   ├── views/
    │   │   └── public/
    │   │       └── ... (Clona toda a estrutura de views públicas)
    │   └── assets/
    │       ├── css/
    │       │   └── public/
    │       │       └── ... (Clona toda a estrutura de CSS público)
    │       ├── js/
    │       └── images/
    │           └── screenshot.png (Imagem de capa do tema)
    └── theme.json

O comando cria automaticamente:

  • O arquivo theme.json com os metadados do tema (nome, descrição, versão, autor e screenshot).
  • Pastas estruturadas para templates Blade e assets estáticos (CSS, JS, imagens).
  • Um link simbólico (ou junction no Windows) em public/themes/nome-do-tema apontando para a pasta resources/assets do tema.

Estrutura do Tema

Os temas residem no diretório /themes na raiz do projeto. Um tema chamado "AstralDark" possui a seguinte estrutura:

themes/
└── AstralDark/
    ├── resources/
    │   ├── views/
    │   │   └── public/
    │   │       ├── site-layout.blade.php      {{-- Layout mestre do site público --}}
    │   │       ├── page-templates/            {{-- Modelos de páginas institucionais --}}
    │   │       └── post-templates/            {{-- Modelos de artigos do blog --}}
    │   └── assets/
    │       ├── css/
    │       │   ├── public/                    {{-- Estilos do front-end --}}
    │       │   ├── auth.css                   {{-- Tela de login --}}
    │       │   └── errors.css                 {{-- Páginas de erro (404, 500) --}}
    │       ├── js/
    │       └── images/
    │           └── screenshot.png             {{-- Prévia exibida na Admin --}}
    ├── theme.json
    └── ThemeServiceProvider.php               {{-- Opcional (Lógica avançada) --}}

O Manifesto (theme.json)

O arquivo theme.json define as informações que aparecem na biblioteca de temas do painel de administração:

JSON{
    "name": "Astral Dark",
    "description": "Um tema focado em tons escuros e constelações.",
    "version": "1.0.0",
    "author": "Equipe Lunar",
    "screenshot": "resources/assets/images/screenshot.png"
}

Sobrescrita de Views (Overrides)

O motor do Lunar Base prioriza as views do seu tema ativo de forma transparente. Se você colocar um arquivo dentro do diretório do tema que corresponda ao caminho das views do core, o sistema carregará o seu arquivo no lugar do original.

Hierarquia de Carregamento:

Ao renderizar um Post, o Laravel busca o arquivo na seguinte ordem:

  • 1º: /themes/NomeDoTema/resources/views/public/post-templates/default.blade.php (Tema ativo)
  • 2º: /resources/views/public/post-templates/default.blade.php (Fallback do core)

Substituindo o Layout Geral do Site:

Para mudar a estrutura inteira do site (como o Header e o Footer), crie o arquivo em:

/themes/NomeDoTema/resources/views/public/site-layout.blade.php

Assets e Links Simbólicos

Os arquivos estáticos (CSS, JS, imagens) do seu tema ficam isolados e são disponibilizados publicamente através de links simbólicos gerados na pasta pública do servidor.

Referenciando Assets no Blade:

BLADE<link rel="stylesheet" href="{{ asset('themes/astraldark/css/public/style.css') }}">
Gerando links manualmente: Ao criar ou copiar um tema manualmente em disco, você pode forçar a criação ou remoção do link simbólico executando: 
BASH# Criar link simbólico do tema
php artisan theme:link NomeDoTema --force

# Remover link simbólico
php artisan theme:link NomeDoTema --unlink

Visualização Prévia (Theme Preview Nativo)

O Lunar Base possui um sistema de Theme Preview embutido no Core. Você não precisa programar nenhuma linha de código adicional no seu tema para que a prévia funcione.

Como funciona para o desenvolvedor e administrador:

  • Isolamento Total: Em Admin → Temas, ao clicar no botão de prévia () de um tema inativo, o sistema abre uma janela modal com o site carregado em um iframe isolado.
  • Criação Automática de Assets: O Core cria os links simbólicos temporários dos arquivos estáticos do tema instantaneamente para que o design renderize com 100% de fidelidade visual.
  • Segurança para Visitantes: A prévia só é visível dentro da janela modal do administrador. Visitantes externos e acessos diretos continuam visualizando o tema oficial ativo no site sem nenhuma interferência.
  • Limpeza Automática: Ao fechar o modal de visualização, a sessão de prévia é destruída e os links temporários são limpos pelo Core automaticamente.

Boas Práticas de Design

  • Não edite o Core: Nunca altere os arquivos dentro de resources/views/public/ diretamente. Copie o arquivo para dentro da pasta do seu tema e faça as alterações por lá.
  • Mantenha a Tag de Screenshots Atualizada: Salve uma captura de tela nítida do seu tema em resources/assets/images/screenshot.png (proporção recomendada: 600×400px) para ilustrar o card do tema no painel de administração.
  • Use os Componentes Globais: Aproveite os Blade Components do sistema (como <x-breadcrumbs />, <x-seo-meta /> e <x-assessibility />) para manter seu tema moderno, acessível e otimizado para SEO.
  • Imagens Otimizadas: Prefira formatos como WebP ou SVG para manter o carregamento das páginas rápido e responsivo.
