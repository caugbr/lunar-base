Visão Geral

O ecossistema do Lunar Base permite que temas e plugins declarem dependências estritas de outros módulos para operar com integridade. O serviço AddonDependencyService centraliza a validação dessas regras e informa a administração caso algum componente essencial esteja ausente ou desativado.

Isso impede que uma loja quebre se o gateway de pagamento for desativado, ou que um tema fique sem estilização caso o plugin de formulários ou sliders não esteja instalado.

As 3 Camadas de Dependência

O sistema processa e consolida dependências a partir de três origens distintas:

  1. 1. Dependências do Tema Ativo

    Lidas a partir do manifesto themes/{folder_name}/theme.json. Aplicam-se unicamente ao tema que estiver ativo no momento da navegação.

  2. 2. Dependências de Plugins Ativos

    Lidas a partir de cada plugins/{folder_name}/plugin.json dos plugins com status ativo (is_active = 1). Plugins inativos têm suas dependências ignoradas até que sejam ligados.

  3. 3. Requisitos Globais do Projeto (Core)

    Lidas do arquivo de configuração do sistema em config/addons.php. Definem plugins obrigatórios para a instalação como um todo (essenciais para as regras de negócio do site).

Como Declarar Dependências

A declaração é feita na chave dependencies.plugins dentro dos manifestos JSON dos addons ou no array de configuração do Core.

1. Em Plugins (`plugin.json`) e Temas (`theme.json`)

JSON{
  "name": "Loja Virtual Pro",
  "version": "1.0.0",
  "dependencies": {
    "plugins": {
      "Asaas": {
        "reason": "Obrigatório para processar pagamentos via PIX e Cartão de Crédito."
      },
      "CorreiosFrete": {
        "reason": "Necessário para o cálculo dinâmico do frete na finalização da compra.",
        "url": "https://meusite.com.br/downloads/correios-frete.zip"
      }
    }
  }
}

2. No Core do Sistema (`config/addons.php`)

PHP// config/addons.php
return [
    'required' => [
        'plugins' => [
            'Asaas' => [
                'reason' => 'Necessário para a liquidação financeira de produtos e assinaturas do sistema.',
            ],
            'LunarApps' => [
                'reason' => 'Plugin com as regras de negócio e geração de relatórios astrológicos.',
                'url'    => 'https://dist.lunarapps.com.br/lunar-apps-latest.zip'
            ],
        ],
    ],
];
Propriedades Disponíveis para cada Dependência:
  • reason (string, opcional) - Texto explicativo exibido para o usuário final justificando a exigência.
  • url (string, opcional) - Link direto de download caso o plugin não esteja publicado no Marketplace oficial.

Como o Core Resolve e Valida

A validação das dependências é acionada via AddonDependencyService::getUnresolvedDependencies(). O fluxo de verificação para cada módulo exigido ocorre da seguinte forma:

  1. Normalização do Nome da Pasta

    O nome declarado é convertido para o padrão do sistema via Str::studly() (ex: meu-plugin vira MeuPlugin).

  2. Verificação de Presença no Disco

    Checa se o diretório físico existe em base_path("plugins/{FolderName}").

  3. Verificação de Estado no Banco

    Consulta o registro na tabela plugins e confirma se a coluna is_active é verdadeira.

  4. Conclusão ou Registro de Pendência

    Se o módulo estiver no disco e com is_active = 1, a dependência é considerada satisfeita. Caso contrário, uma pendência é criada com seu respectivo diagnóstico.

Integração com o Marketplace

Se uma dependência estiver ausente do servidor (não existe no disco) e nenhuma url direta tiver sido informada no manifesto, o AddonDependencyService aciona o AddonMarketplaceService.

O sistema consulta o catálogo remoto oficial de addons (marketplace.json), localiza o item pelo nome e extrai automaticamente a sua download_url oficial.

Instalação Automatizada:

Graças a essa ponte, a interface administrativa do Lunar Base consegue oferecer ao usuário um botão direto de "Instalar e Ativar Dependência" com apenas um clique, sem exigir download manual de arquivos compactados.

Estados de Resolução

Cada item retornado na lista de pendências não resolvidas é classificado em um de dois estados:

1. Status: inactive (Inativo)

O plugin já está baixado e presente na pasta plugins/, porém está desativado no banco de dados.

Ação esperada na UI: Exibir botão de ação rápida para "Ativar Plugin".

2. Status: missing (Ausente)

Os arquivos do plugin não existem no servidor.

Ação esperada na UI: Exibir botão para "Instalar via Marketplace" (se houver download_url) ou alerta de instalação manual.

Exemplos Práticos

Exemplo 1: Tema Exigindo Plugin de Formulário

JSON (themes/Moderno/theme.json){
  "name": "Moderno",
  "version": "2.1.0",
  "dependencies": {
    "plugins": {
      "ContactForm": {
        "reason": "Necessário para a renderização das seções de contato da página inicial."
      }
    }
  }
}

Exemplo 2: Plugin que Extende outro Plugin

JSON (plugins/LunarApps/plugin.json){
  "name": "Lunar Apps",
  "version": "1.2.0",
  "dependencies": {
    "plugins": {
      "Asaas": {
        "reason": "O Lunar Apps necessita do plugin Asaas ativo para emissão de cobranças e recepção de webhooks."
      }
    }
  }
}

Exemplo 3: Consumindo as Pendências via Controller/Middleware

PHPuse App\Services\AddonDependencyService;

public function checkDependencies(AddonDependencyService $dependencyService)
{
    $unresolved = $dependencyService->getUnresolvedDependencies();

    if (!empty($unresolved)) {
        // Envia as pendências para renderização no painel
        view()->share('unresolvedAddons', $unresolved);
    }
}

Boas Práticas

  • Sempre informe o nome da pasta em StudlyCase no manifesto. Embora o sistema normalize strings, declarar exatamente o mesmo nome da pasta (ex: "ContactForm" para a pasta plugins/ContactForm) evita ambiguidades.
  • Forneça sempre o campo reason. Mensagens amigáveis evitam que usuários finais desativem plugins vitais por engano e abram chamados de suporte.
  • Prefira nomes compatíveis com o Marketplace oficial. Ao requisitar plugins de terceiros que já estão listados no catálogo oficial, você dispensa a necessidade de declarar o campo url, tornando a manutenção de versões automática.
  • Não crie dependências circulares. Evite cenários onde o Plugin A depende do Plugin B, e o Plugin B depende do Plugin A, a menos que isso seja estritamente planejado para carregamento condicional.
  • Use o config/addons.php apenas para o que for estrutural. Reserve a configuração global do Core apenas para módulos sem os quais o propósito principal do projeto não pode funcionar.
