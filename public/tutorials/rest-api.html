Introdução

O Lunar Base atua como um Headless CMS Híbrido. Ele pode servir páginas tradicionais em Blade e, simultaneamente, disponibilizar uma API REST padronizada e de alta performance para ser consumida por front-ends modernos (como Vue.js, Nuxt, React, Next.js ou aplicativos móveis).

A API foi desenhada sob o conceito de Entrega de Conteúdo Read-Only. A gestão e edição são mantidas exclusivamente no painel administrativo, garantindo superfície de ataque mínima, resposta ultra-rápida e facilidade de cache.

Endpoints Nativos do Core

Por padrão, o ecossistema disponibiliza os seguintes endpoints sob o prefixo /api/v1/:

Método Endpoint Descrição
GET /api/v1/site Metadados globais (nome, descrição, tema ativo) e o menu principal estruturado.
GET /api/v1/posts Listagem paginada e filtrável dos artigos do blog.
GET /api/v1/posts/{slug} Retorna o artigo individual com autor, mídias, taxonomias e shortcodes processados.
GET /api/v1/pages Listagem das páginas estáticas/institucionais.
GET /api/v1/pages/{slug} Retorna uma página estática específica pelo seu slug.
GET /api/v1/taxonomies Lista todas as taxonomias (categorias, tags, etc.) e seus respectivos termos.
GET /api/v1/resolve Resolvedor dinâmico para mapear URLs amigáveis em aplicações SPA.

Resolvedor Universal de Permalinks

Aplicações Single Page (como Vue ou Nuxt) utilizam roteamento dinâmico no cliente e não sabem de antemão se uma URL digitada pelo visitante (ex: /institucional/sobre ou /blog/post-1) trata-se de uma página, post ou recurso de plugin.

O endpoint GET /api/v1/resolve?path=/sua-url executa a inteligência de rotas do sistema e retorna os dados corretos envelopados em uma única chamada HTTP:

Exemplo de Resposta: GET /api/v1/resolve?path=/post-1

JSON{
    "success": true,
    "resolved": true,
    "type": "post",
    "data": {
        "id": 1,
        "title": "Meu Primeiro Post",
        "slug": "post-1",
        "url": "http://localhost:8000/post/post-1",
        "author": { "id": 1, "name": "Cau Guanabara" },
        "content": {
            "raw": "Texto com [shortcode]",
            "rendered": "<p>Texto com componente HTML</p>"
        }
    }
}

Arquitetura Guiada por Schemas

A API do Lunar Base é impulsionada pela classe App\Support\ApiRegistry. Em vez de criar um controller ou um JsonResource para cada nova tabela, a API lê Schemas Declarativos.

Navegação por Ponto

Strings simples usam a notação de ponto nativa do Laravel (ex: 'author.name' ou 'thumbnail.url') para extrair dados aninhados sem escrever código.

Campos Calculados

Closures (funções anônimas) permitem processar shortcodes ou formatar listas dinâmicas em tempo de execução (ex: ContentHelper::parseShortcodes()).

Proteção de Dados

Apenas as chaves explicitamente declaradas no Schema são expostas na resposta JSON, impedindo o vazamento acidental de campos sensíveis.

Expansão via Plugins

Plugins não precisam registrar novos controllers para expor dados na API. Basta invocar o método estático ApiRegistry::register() dentro do método boot() do seu ServiceProvider.

Exemplo: Registrando a API do Plugin de FAQ

PHPuse App\Support\ApiRegistry;

public function boot(): void
{
    // Registra a entidade 'faqs' na API
    ApiRegistry::register('faqs', [
        'source_item' => fn($slug) => getOption("faq_{$slug}"),
        'schema'      => [
            'titulo'    => 'title',
            'slug'      => 'slug',
            'perguntas' => 'items',
        ]
    ]);
}

Ao realizar o registro acima, a rota GET /api/v1/faqs/vendas estará instantaneamente disponível para o front-end público com contrato JSON padronizado.

Filtros, Busca e Paginação

O controlador genérico da API aceita os seguintes parâmetros de Query String em chamadas de listagem (GET /api/v1/{entity}):

Parâmetro Tipo Padrão Descrição
page int 1 Página atual da paginação.
per_page int Configuração do painel Quantidade de itens retornados por página.
search string null Filtra os resultados por palavra-chave nos campos marcados como searchable no Schema.
Proteção Rate Limit: Por padrão, a API é protegida por um limitador de taxa (RateLimiter) configurado para 60 requisições por minuto por endereço IP, garantindo estabilidade ao servidor.
