Introdução

O Lunar Base disponibiliza um serviço centralizado de AssetManager (inspirado no modelo de enqueue). Ele resolve o problema comum de plugins e temas que precisam injetar folhas de estilo (CSS), scripts externos (JS) ou configurações dinâmicas de backend sem poluir ou engessar os arquivos de layout Blade.

Prevenção de Duplicatas

Cada asset é registrado com um identificador único (handle). Se dois plugins solicitarem a mesma biblioteca (ex: Chart.js), ela será carregada apenas uma vez.

Posicionamento Automático

Controle se os scripts devem ser injetados no cabeçalho ou no rodapé, com suporte nativo a atributos como defer e controle de versão (cache-busting).

Injeção Dinâmica de Variáveis

Passe dados, chaves de API e tokens CSRF do PHP diretamente para o JavaScript sem misturar tags Blade dentro de arquivos .js.

Diretivas Blade (@headerAssets e @footerAssets)

Para que o sistema renderize a fila de assets enfileirados, os layouts principais (tanto da administração quanto dos temas públicos) devem incluir as duas diretivas nas posições corretas:

HTML (Layout Base)<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <title>@yield('title', config('app.name'))</title>

    <!-- CSS nativo do layout -->
    <link rel="stylesheet" href="{{ asset('css/style.css') }}">

    <!-- 💡 Renderiza todas as tags <link> e scripts síncronos do cabeçalho -->
    @headerAssets
</head>
<body>
    @yield('content')

    <!-- 💡 Renderiza todas as tags <script> e scripts inline no final do <body> -->
    @footerAssets
</body>
</html>

Helpers Globais

O ecossistema disponibiliza 4 funções helpers globais prontas para uso em qualquer Controller, Middleware, ServiceProvider de Plugin ou arquivo Blade:

Helper Finalidade
add_style() Enfileira um arquivo CSS externo ou local na tag <head>.
add_script() Enfileira um arquivo JavaScript externo ou local (no header ou footer).
add_inline_style() Injeta um bloco de regras CSS inline gerado dinamicamente via PHP.
add_inline_script() Injeta um bloco de código JavaScript inline antes dos scripts no rodapé.

Enfileirando Folhas de Estilo (CSS)

Utilize a função add_style() para adicionar arquivos CSS. O sistema cuida da renderização de tags <link rel="stylesheet"> formatadas com identificadores únicos:

PHPadd_style(
    string $handle,               // Identificador único (ex: 'leaflet-css')
    string $src,                  // URL completa ou caminho via asset()
    array $deps = [],             // Dependências (opcional)
    string $version = '1.0.0',    // Versão para controle de cache (?v=1.0.0)
    string $media = 'all'         // Atributo media (ex: 'all', 'screen', 'print')
);

Exemplo Prático:

PHP// No boot() de um plugin ou em um Controller:
add_style('leaflet-maps', 'https://unpkg.com/leaflet@1.9.4/dist/leaflet.css', [], '1.9.4');
add_style('meu-plugin-custom', asset('plugins/meuplugin/css/style.css'), [], '1.0.2');

Enfileirando Scripts (JS)

Utilize a função add_script() para carregar bibliotecas ou arquivos de comportamento JavaScript:

PHPadd_script(
    string $handle,               // Identificador único (ex: 'chart-js')
    string $src,                  // URL do script
    array $deps = [],             // Dependências
    string $version = '1.0.0',    // Versão (?v=1.0.0)
    bool $inFooter = true,        // true = renderiza no @footerAssets | false = no @headerAssets
    bool $defer = false           // Adiciona o atributo 'defer' na tag <script>
);

Exemplo Prático:

PHP// Carrega o Chart.js no footer com defer ativado
add_script('chart-js', 'https://cdn.jsdelivr.net/npm/chart.js', [], '4.4.0', true, true);

// Carrega o script de rastreamento do plugin
add_script('tracker-events', asset('plugins/tracker/js/eventTracker.js'), ['chart-js'], '1.0.0', true, true);

Injeção Dinâmica (Inline CSS e JS)

Uma das maiores vantagens do AssetManager é permitir que o backend envie variáveis computadas em tempo de execução para o JavaScript ou CSS sem misturar lógica Blade em arquivos estáticos.

1. Passando Configurações para o JavaScript (`add_inline_script`)

Ideal para injetar URLs de API, tokens CSRF ou dados vindos do banco de dados:

PHP// No ServiceProvider do Plugin ou Controller:
$eventUrl = route('tracker.api.event');
$csrfToken = csrf_token();

add_inline_script("window.TRACKER_CONFIG = { eventUrl: '{$eventUrl}', csrfToken: '{$csrfToken}' };");
add_script('tracker-js', asset('plugins/tracker/js/eventTracker.js'), [], '1.0.0', true, true);

Dentro do seu arquivo eventTracker.js externo e estático, basta ler o objeto global window.TRACKER_CONFIG!

2. Injetando Cores e Estilos Dinâmicos (`add_inline_style`)

Ideal quando o administrador escolhe cores ou fontes personalizadas no painel administrativo:

PHP$corPrimaria = setting('general.theme_primary_color', '#2563eb');

add_inline_style(":root { --color-brand: {$corPrimaria}; }");

Como Funciona por Baixo dos Panos (Singleton)

A classe App\Services\AssetManager é registrada como um Singleton no Service Container do Laravel:

PHP// No AppServiceProvider:
$this->app->singleton(AssetManager::class, function () {
    return new AssetManager();
});

Por que isso é importante?

  • Durante uma mesma requisição HTTP, todas as chamadas a add_script() ou add_style() feitas por controllers, middlewares ou plugins diferentes compartilham a mesma fila em memória.
  • Quando o Blade atinge a tag @headerAssets ou @footerAssets, ele consulta a instância única na memória e imprime as tags HTML finais sem duplicatas.
  • Ao término da requisição, a memória é limpa automaticamente pelo PHP/Laravel, garantindo que os assets de uma página nunca vazem para outra.

Boas Práticas para Plugins e Temas

  • Nomes de Handles Semânticos: Use identificadores claros com prefixo do seu plugin (ex: tracker-chart-js, caminho-custom-css) para evitar colisões acidentais.
  • Prefira Scripts no Footer com Defer: Salvo casos estritamente necessários no <head>, mantenha $inFooter = true e $defer = true para não bloquear a renderização da página (melhorando o score de performance e Core Web Vitals).
  • Não duplique tags <script> soltas no Blade: Se seu plugin precisa carregar uma biblioteca JS, use sempre add_script() no ServiceProvider ou Controller em vez de colar tags <script src="..."> no meio do corpo HTML.
  • Use Controle de Versão: Ao atualizar os arquivos CSS/JS do seu plugin, altere o parâmetro de versão (ex: '1.0.1') para forçar a renovação de cache nos navegadores dos visitantes.
